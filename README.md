# Shift Studio — 勤務形態・職員別条件に対応するシフト最適化

Python / Streamlit / Google OR-Tools CP-SAT を使う、ローカル実行のシフト作成ツールです。

実装に興味がある方向け：[技術ノート（通常の利用には不要）](docs/TECHNICAL_STACK.md)

## Windows用exeの作成と配布

- プロジェクト直下の [build_exe.bat](build_exe.bat) を実行すると配布用の単一exeをdist/に出力します。[ShiftStudio.spec](ShiftStudio.spec) はルートに置いたまま、src/のソースとルートのStreamlit設定を参照します。
- batは依存ライブラリ導入、全テスト、PyInstallerビルド、生成exe内のセルフテストを順に実行します。エラーの場合は終了コード1で停止します。
- ビルドにはWindows x64、Python 3.12、初回のライブラリ取得用インターネット接続が必要です。既存の `.venv` があれば使用し、なければ `py -3.12` で作成します。
- 配布するのは `dist/ShiftStudio.exe` です。Python、OR-Tools、画面用資源を内包した単一exeであり、利用者側にPythonのインストールは不要です。利用手順としてこのREADMEも添付してください。
- exeをダブルクリックするとコンソールと既定ブラウザーを開きます。コンソールを開いたまま利用し、終了時はコンソールでCtrl+Cを押してください。ブラウザーを閉じただけではサーバーは終了しません。
- 127.0.0.1のみで待受します。8501番ポートが使用中なら空いている別ポートを選び、コンソールにURLを表示します。ブラウザーが開かない場合は、そのURLを手動で開いてください。
- 自動ブラウザー起動を止める場合は `ShiftStudio.exe --no-browser`、起動ポートを指定する場合は `ShiftStudio.exe --port 8510` を使用できます。`--self-test` は同梱ソルバー・画面・シフト生成の検証を行って終了します。
- 単一exeは起動時に一時フォルダーへ展開するため、起動に数秒以上かかり、一時領域にも空き容量が必要です。exeと同じフォルダーへの書込みは不要です。
- 生成物はWindows x64向けです。過去のビルドの検証実績は下記を参照してください。更新後のソースと既存exeが同じ機能とは限りません。配布先のWindows・セキュリティ設定でも別途確認してください。macOS・Linuxでは実行できません。
- コード署名は付与していません。Windows SmartScreen等が未署名アプリの警告を表示する場合があります。組織の配布・署名・セキュリティ方針に従ってください。
- 入力内容はexeにも保存されません。職員・希望休・回避ペア・個別勤務時刻・曜日固定・シフト回避CSVは別途保存・管理してください。exe更新時は起動中のexeを終了してから再ビルドしてください。
- サードパーティーライブラリを含むため、公開・再配布時は各ライブラリのライセンスと通知義務を確認してください。

## 起動

この作業環境には専用仮想環境 `.venv` と必要ライブラリを導入済みです。

- Windowsではルートの [start_app.cmd](start_app.cmd) をダブルクリックします。内部では [src/app.py](src/app.py) をStreamlitで実行します。ブラウザーで http://127.0.0.1:8501 を開きます。
- VS Codeではルートの [.vscode/tasks.json](.vscode/tasks.json) にある「ターミナル → タスクの実行 → シフト最適化を起動」を選択できます。
- 終了するときは、起動したターミナルで Ctrl+C を押してください。

別のPCで初期セットアップする場合（Python 3.12推奨）、プロジェクトルートを作業ディレクトリとしてPowerShellで以下を実行します。[requirements.txt](requirements.txt) から実行・テスト用の依存ライブラリを再導入します。exeビルド用の依存定義は [requirements-build.txt](requirements-build.txt) です。

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run src/app.py
```

任意で、同じ仮想環境からローカル起動入口 [src/launcher.py](src/launcher.py) を実行することもできます。

```powershell
.\.venv\Scripts\python.exe src/launcher.py
```

## 操作

1. 左側のカレンダーで作成期間の開始日と終了日（最大62日）を選び、各シフト最低人数 N（1以上。1ならワンオペ）を指定します。
2. サイドバーの「役職・配置要件」で役職名、配置条件（必須なし／各シフト／1日のどこか）、必要人数を設定します。初期値は主任を各シフト1人です。
3. 職員の登録画面で職員ID、氏名、各「役職:名前」チェック欄を設定します。初期値は架空の職員15人、うち主任6人です。「主任以上」は旧CSV互換用で、現在の役職判定には使用しません。
4. 休み希望の画面で、職員IDと日付を1件ずつ登録します。日付は `YYYY-MM-DD` です。CSVからの読込も可能です。
5. 必要に応じて「配慮・個別勤務」で同一シフトペア（ハード／ソフト選択）、回避ペア、職員別の毎回／日付指定の勤務時刻を入力します。各入力表はCSV読込・保存に対応します。
6. 「04 曜日固定・シフト回避」で、必要な職員の曜日固定勤務と、避けたいシフト（複数選択）・優先度を設定します。両方とも専用CSVの読込・保存が可能です。
7. 「シフトを作成」を押します。必須条件が両立しなければ、シフト表は出力しません。回避ペアの同時配置や回避希望シフトへの配置が残るだけなら作成できます。
8. 作成したシフト表、日別配置、職員別集計、月別労働時間、個別勤務明細、ペア配慮結果、曜日固定結果、シフト回避結果をCSVで保存します。Excel向けのUTF-8 BOM形式です。
各シフトの**標準時間内の各時間帯で最低N人**、設定した役職要件、1人1日1勤務は、どの勤務形態でも必須条件です。区分への割当人数だけでは判定せず、個別勤務時刻による欠けも検査します（休憩取得時刻は対象外）。

サイドバーの「シフト時間の詳細設定」から、現在の各シフトの標準開始・終了時刻を分単位で変更できます。
日付をまたぐ場合は「翌日終了」を選択してください。例えば23:30〜翌08:15の設定も可能です。
時間変更も入力条件の変更として扱い、以前の結果は非表示になります。

### 前日より早い出勤を禁止する（任意・初期値は無効）

サイドバーの「追加の勤務ルール」で「前日より早い出勤を禁止する」を選択すると、同じ職員が**隣接する暦日の両方に勤務を開始する場合**、翌日の開始時刻を前日と同じか遅くする必須条件を追加します。初期値は無効です。無効時でも最低休息などの既存条件は守ります。

- 例：09:00→翌日08:00は禁止、09:00→翌日09:00／10:00は許可します。ただし、許可例でも最低休息など他の条件を満たす必要があります。分単位で比較し、10:00→09:59も禁止します。
- 比較するのはシフト名や一覧の順序ではなく、**日付指定の個別勤務時刻 → 毎回の個別勤務時刻 → 標準時刻**の順で解決した実際の開始時刻です。同じ「日勤」でも日付によって開始が早まれば対象です。
- **勤務開始日の暦日**を基準にします。月曜20:00〜火曜08:00の夜勤→火曜09:00開始は、実際に1時間の休息があっても20:00→09:00として禁止します。最低休息を0時間にしてもこの禁止は変わりません。
- **勤務開始の割当がない日を挟むと開始時刻の比較だけをリセット**します。希望休の登録がなくても同じです。月曜20:00→火曜は開始割当なし→水曜09:00は、この条件だけでは禁止しません。前日の夜勤が持ち越す日は、暦日全体が休日という意味ではありません。
- **最低休息は独立して必ず検査**します。中1日空いても終了から次の開始までの休息が不足すれば作成不可です。例えば月曜23:00〜火曜22:00→水曜08:00は休息10時間なので、最低11時間なら不可です。
- 曜日固定・必要人数・役職・希望休・月間時間などと矛盾しても、この条件や他の必須条件を緩和して解を作りません。両立しなければ作成不可です。
- 月末→翌月初日でも暦日が隣接していれば比較します。一方、**対象期間の初日は期間外の前日勤務と比較しません**。期間外の勤務を入力する機能はないため、期間境界の開始時刻・休息・連勤は運用で別途確認してください。
- チェックの変更も以前の結果・結果CSVを非表示にするため、再生成してください。作成条件JSONには「前日より早い出勤を禁止」を真偽値で記録します（JSONの再読込は未対応）。APIの `Settings.nondecreasing_start_times` はキーワード専用・既定値 `False` で、厳密な `bool` のみ受け付けます。`1` や `None` は入力エラーです。

### 勤務形態と休憩

- 「勤務形態」で三交代・二交代・日勤のみ・カスタムを切り替えます。カスタムは1〜8シフトで、名称も変更できます。
- 三交代の初期値は従来どおり00–08、08–16、16–24時（休憩0分）。二交代は日勤08–20、夜勤20–翌08時（休憩0分）。日勤のみは09–18時（休憩60分）です。
- これらは形式例で、法令準拠の勤務時間を保証するプリセットではありません。実際の勤務・休憩に変更してください。
- 各シフトの開始・終了・翌日終了・休憩分を個別設定できます。休憩は勤務長未満にしてください。
- 各シフトの**標準時間内の各時間帯で最低N人**、設定した役職要件、1人1日1勤務は、どの勤務形態でも必須条件です。区分への割当人数だけでは判定せず、個別勤務時刻による欠けも検査します（休憩取得時刻は対象外）。
- シフト名を変更・削除したとき、職員の固定シフトは自動で別勤務に変更しません。古い固定値が残る場合は入力エラーとなるため、職員側も修正してください。

### 職員別の勤務条件

職員一覧の右側の列で設定できます。表を横スクロールすると時間設定の列が表示されます。

| 列 | 設定内容 |
|---|---|
| 固定シフト | 制限なし、または現在のシフト名。深夜を選べば深夜のみ割当可能。許可勤務帯の制限であり、毎日・毎週の出勤を強制する曜日固定勤務とは別設定です |
| 月間実労働時間プリセット | 未設定、80・120・140・160・168時間、カスタム |
| 月間実労働時間（時間） | プリセットがカスタムの場合にだけ使用。小数で指定可能、整数分に四捨五入。休憩控除後の実労働時間を必ず完全一致させる |
| 月間上限（時間） | 必ず守る上限。空欄は未設定、0時間は勤務禁止 |

月間実労働時間は月間上限以下にしてください。「未設定」の職員には指定時間の制約を付けません（固定シフト・上限などの条件は適用します）。
カスタムで0時間を指定すると勤務禁止です。未設定とは異なります。カスタムを選んだ場合、時間欄は必須です。
指定した時間は必須条件であり、近い時間で代用しません。必要人数、希望休、勤務時間単位などと両立しなければ作成不可になります。
例えば日割り後の指定時間が7時間45分でも、許可された勤務が8時間だけなら完全一致できません。
80時間を指定して8時間勤務を割り当てる場合、1月全31日なら10勤務で一致しますが、1月の14日間では日割り後の2168分に一致できません。

### 月間時間の適用ルール

- 暦月ごと・職員ごとに**休憩控除後の実労働時間**を集計します。
- 月の一部を作成する場合、指定時間は `月間実労働時間 × 対象日数 ÷ その月の日数` を整数分に四捨五入し、その分数に必ず完全一致させます。
- 月をまたぐ期間は月ごとに別々に計算します。例：1月31日から2日間なら1月・2月それぞれ1日分の指定時間です。複数月の差を相殺することはできません。
- **月間上限は日割りしません**。上限は、作成対象内の勤務時間の月別合計に対して必ず守ります。
- 月をまたぐ夜勤は、休憩控除後の全労働時間を**勤務開始月**に計上します。実際の暦日への時間按分は行いません。
- 対象期間外の既存勤務を含めた月全体の上限管理はできません。月間上限を運用で保証する場合は月全体を対象に計画し、期間外・月境界の実績も別途照合してください。
- 結果の「月別労働時間」タブ・CSVには「実労働時間」（生成した勤務の合計）、「対象期間の指定実労働時間」、「指定との差（時間）」、「月間上限（時間）」、「固定シフト」を表示します。指定ありの差は必ず0です。指定なしの指定時間・差は空欄になります。

### 同一シフトペア（ハード／ソフト選択）

「03 配慮・個別勤務」の「同じシフトにするペア」に職員ID A（新人など）・職員ID B（教育担当など）を登録します。

- **条件**：「ハード（必須）」は必ず守り、他の必須条件と両立しなければ作成不可にします。「ソフト（できるだけ）」は未達を許容し、同じシフトになるよう優先します。空欄はハードです。
- **適用範囲**：「Aの勤務時にBを合わせる」（初期値）は、Aの勤務にBを同じ日・同じシフトへ配置します。Bだけの勤務は許可し、Aが休みの日にBも休む必要はありません。「双方向（休日も合わせる）」は両方向に適用し、勤務日・シフト区分・休日を揃えます。ソフトの場合はこの一致を保証しません。
- **勤務開始日とシフト区分**で判定します。月をまたぐ夜勤も勤務開始日が基準です。個別勤務時刻を同じにする機能ではなく、勤務時間全体の付き添いや休憩中の教育担当の在席は保証しません。必要なら個別時刻も確認してください。
- 出勤日自体を強制する設定ではありません。両者とも休みなら未達ではなく、Aを休みにすることで条件を満たす場合もあります。必要な出勤は曜日固定や月間実労働時間などで別途設定してください。
- **優先度**（低め・普通・高め・最優先、空欄は普通）はソフト時のみ使用します。相手が同日・同区分にいない対象勤務1件ごとに数えます。双方向でAとBが別シフトなら2件、片方だけの出勤なら1件です。
- 最適化の優先順位は **すべての必須条件 → 総配置数の抑制 → 同一シフト未達・回避ペア衝突・回避希望シフトへの配置の重み付き合計 → 勤務回数の偏り** です。ソフトだけを目的に配置人数は増やしません。ハードにより必須の追加配置が必要になる場合はあります。
- 最大200組。未登録ID・同一職員・同じ組の重複（逆順や条件違いを含む）は入力エラーです。双方向を指定したい場合は同じ組を逆順で追加せず、適用範囲を変更してください。回避ペアとの併用は可能ですが、同一シフトのハードが回避希望より優先されます。
- 専用CSVの列は「職員ID A,職員ID B,条件,適用範囲,優先度」です。条件と適用範囲は画面と同じ日本語の選択肢を使用します。入力表をCSV保存して再利用できます。作成条件JSONにも記録します（JSONの再読込は未対応）。
- 結果に未達勤務数と優先度別の件数、詳細・「同一シフトペア結果 CSV」に相手不在の職員・日付・シフトを表示します。未達がなければ詳細は空表です。入力・条件・適用範囲・優先度を変更すると古い結果を非表示にし、再生成が必要です。
- この機能の追加では既存の配布exeを更新していません。exeで利用する場合は再ビルドが必要です。

### 回避ペア（ソフト制約）

「配慮・個別勤務」で職員IDの組を登録すると、**同じ勤務開始日・同じシフト区分**への同時配置をできるだけ減らします。勤務時刻が重なっていても、別シフト区分の職員同士は対象外です。同一区分なら個別時刻が重ならなくても同時配置として数えます。

- 回避は保証しません。希望休・必要人数・役職・月間時間などの必須条件を緩和することはありません。
- 優先順位は **総配置数の抑制 → 同一シフト未達・ペア衝突と回避希望シフトへの配置の抑制（優先度の高いものほど重視） → 勤務回数の偏りの改善** です。ペア回避・シフト回避だけを目的に配置人数を増やしません。
- 優先度は4段階から選びます。空欄なら普通です。最大200組で、未登録ID・同一職員の組・同じ組の重複（逆順を含む）は入力エラーです。
- 優先度の目安は **低め＝できれば、普通＝標準的な配慮、高め＝優先して守る、最優先＝他の配慮より優先** です。内部では低め1・普通5・高め20・最優先100として扱い、上の段の1回はすぐ下の段の4〜5回分に相当します。回避率や確率を表すものではなく、ペア間およびシフト回避との相対的な優先度です。
- 優先度を上げても総配置数を増やしたり必須条件を緩めたりしません。避けられない場合や、別のペア衝突・シフト回避配置を避けるほうが全体の合計を下げられる場合は、優先度の高いペアでも衝突が残ることがあります。
- 結果の指標に衝突回数と優先度別の件数（例: 最優先 0 / 高め 1 / 普通 2 / 低め 0）、詳細表・ペア配慮結果CSVに該当する組・日付・シフト・優先度を表示します。回避不能なペアが残っても、それだけで作成不可にはしません。

### 毎週の曜日固定勤務（必須条件）

「04 曜日固定・シフト回避」の入力表に職員ID・曜日（月〜日）・シフトを1行ずつ登録します。作成期間内で該当する**勤務開始日の曜日**すべてについて、指定シフトへの出勤を必須にします。週や月をまたいでも繰り返し適用し、期間外の曜日は対象にしません。

- 例：S01・月・日勤なら、期間内の毎週月曜の日勤を必須にします。2026年1月26日から8日間なら1月26日と2月2日が対象です。**他の曜日を休日にしたり、同じシフトだけに制限したりはしません**。
- 例：月曜開始の夜勤20:00〜翌08:00を固定すると、火曜朝まで勤務します。火曜に希望休があれば矛盾して作成不可になります。曜日は勤務終了日では判定しません。
- 曜日固定は勤務時刻を上書きしません。**日付指定の個別勤務時刻 → 毎回の個別勤務時刻 → 標準シフト時刻**の順で設定済みの時刻・休憩を適用します。希望休、休息、連勤、月間実労働時間・上限なども実際の時刻で検査します。
- 希望休、職員一覧の固定シフト（許可勤務帯）、必要人数・役職、休息・連勤、指定実労働時間・上限と両立しなければ、曜日固定を解除せず作成不可にします。毎週の全該当日に必ず実行可能な計画を作れるという保証ではありません。
- 同じ職員・曜日は1件だけです。同じシフトでも重複は禁止です。未登録ID、不正な曜日、存在しないシフトは入力エラーです。全員の曜日固定などにより、最低人数を超える配置が必要になる場合があります。
- 職員一覧の旧「固定シフト」は割当可能な勤務帯を制限するだけで、曜日ごとの出勤指定ではありません。曜日固定と併用する場合は整合する設定にしてください。

### 職員ごとのシフト回避（複数選択・ソフト条件）

同じタブで職員ごとに避けたいシフトを複数選択し、優先度（低め・普通・高め・最優先）を選びます。未選択ならシフト回避の希望なしです。回避は勤務禁止ではなく、曜日固定などの必須条件を優先します。例えば月曜の深夜を必須にし、深夜・準夜を回避しても、月曜の深夜は残ります。

- 回避対象シフトへの**実際の配置1回ごとに1回**と数えます。深夜・準夜の2種類を選んでも、深夜1勤務は1回分です。同じ優先度のシフト回避配置1回とペア衝突1回は同じ重さで比較します。
- ペア回避を先に完了してからシフト回避するのではなく、**同一シフトペア（ソフト）の未達も含め、優先度で重み付けした合計**を最小化します。その後に勤務回数の公平性を改善します。重みの目安は回避ペアと同じで、数値は回避確率ではありません。
- 代替職員がいれば避けられる場合も、必要人数・曜日固定などにより避けられない場合もあります。回避希望への配置が残ることだけでは作成不可にしません。回避のために配置数を増やしたり、必須条件を緩和したりしません。
- 指標「回避希望シフトへの配置」に回数を表示します。結果の詳細表・CSVで日付・職員・回避シフト・優先度を確認してください。

### 手修正と、一部を固定した作り直し

作成結果の「✏️ 手修正して、残りだけ作り直す」で、シフト表のマスを直接書き換えられます。書き換えたマスは固定になります（シフト表では枠付きで表示）。

- **① マスの書き換え**：書き換えたマスは、その内容で固定します。
- **② 今の内容のまま固定するマス**：チェックを付けたマスを今の内容（勤務または休み）のまま固定します。「全日固定」でその職員の全日を固定します。前回までの固定にはチェックが付いており、外すと次の作り直しで固定を解除します。①で書き換えたマスはチェックがなくても固定します。

- **固定して残りを作り直す**：固定したマスはそのままに、それ以外のマスは**今のシフトからの変更数が最小**になるように作り直します。必須条件はすべて守り、変更数が同じなら従来どおり配置数→配慮→偏りの順で選びます。結果に「固定以外で変わったマス数」を表示します。
- **手修正のまま検査**：作り直さずに、手で書き換えた状態が必須条件を満たすかを検査し、違反を一覧表示します。
- **固定をすべて解除**：固定を取り消します。「シフトを作成」で最初から作り直した場合も固定は解除されます。固定は作り直しを重ねても残ります。
- 勤務にするマスはシフト名、休みにするマスは「休」（「希望休」「休日」も休み扱い）を選びます。シフト統合した日は、一覧で最も上のシフト名を選びます。
- 休日・希望休への勤務、許可されていないシフトの固定は入力エラーです。固定したマスが他の必須条件と両立しない場合は作成不可とし、条件を緩めません。

### 日・曜日・シフトごとの必要人数

サイドバーの「各シフトの最低人数 N」「各シフトの最大人数（0＝上限なし）」が全体の基本値です。「必要人数」タブの表で、日付・曜日・シフトごとに最低人数と最大人数を上書きできます。どちらも必須条件（ハード）です。

- 日付も曜日も空欄なら毎日、シフトが「全シフト」ならその日のすべてのシフトが対象です。日付と曜日は同時に指定できません。
- 最大人数が空欄なら上限なし。最低＝最大にすると「この日はこの人数だけ」になります。最低0人ならそのシフトは不要で、誰かが入る場合だけ役職要件（各シフト）を課します。
- 複数の設定が当てはまる場合は **日付指定 → 曜日指定 → 毎日 → 基本設定** の順に、同じ段ではシフト指定を全シフトより優先します。値は足し合わせず、最も優先する1件を使います。シフト統合した日は、一覧で最も上のシフトの設定を使います。
- 「適用結果の確認」で日ごと・シフトごとの必要人数（例: 2〜3人、4人、2人以上）を確認できます。結果の日別配置にも「必要人数」列を表示します。
- 入力表はCSV（列: 日付,曜日,シフト,最低人数,最大人数）で保存・読み込みできます。

### 休日設定（カレンダー）

「休日設定」タブのカレンダーで、シフトを作らない休日を設定します。初期値は土日と国民の祝日（振替休日・国民の休日を含む。2016年以降の祝日法と2019〜2021年の特例に対応、外部通信なしで計算）です。

- 日付をクリックすると休日⇔出勤日を切り替えます。休日でない日を休日に、土日祝を出勤日にできます。変更した日には✎が付き、下の一覧に表示されます。
- 「土日祝の休みにリセット」で変更を取り消し、土日祝の休みに戻します。「すべて出勤日にする」は24時間・年中無休の職場向けです。
- 休日は誰も勤務せず、必要人数・役職要件・曜日固定を適用しません。シフト表には「休日」と表示します。
- 今後、祝日法の改正や臨時の祝日があった場合は、カレンダーで個別に切り替えてください。

### 日ごとのシフト統合

「05 シフト統合」の入力表に日付と統合するシフト（2つ以上、複数選択）を登録すると、その日だけ選んだシフトを1勤務にまとめます。例：早番①＋早番②を統合すると、1人が両方の時間を担当します。早番①＋早番②＋中番のような3つ以上の統合や、同じ日に別々の統合を複数登録することもできます（同じシフトを同じ日の2つの統合に入れることはできません）。

- 統合後の勤務時刻は最初のシフトの開始から最後のシフトの終了までです。時間が途切れるシフトの組み合わせは入力エラーです。休憩は空欄なら統合元の休憩の合計で、分で上書きできます。
- 最低人数・役職要件（各シフト）は統合後の1勤務として判定します。結果の表示は「早番①+早番②」、職員別集計は一覧で最も上のシフトに計上します。
- 固定シフト・曜日固定・回避シフトは、統合元のどれかに該当すれば統合後の勤務に適用します。統合日は毎回（日付空欄）の個別勤務時刻を使わず、日付指定の個別勤務時刻は一覧で最も上のシフトで指定します。
- 入力表はCSVで保存・読み込みできます（統合するシフトはJSON配列、例: `["早番①", "早番②"]`）。

### 職員別の毎回／日付指定の勤務時刻

「配慮・個別勤務」で、職員ID・シフトごとに開始・終了・翌日終了・休憩分を指定できます。適用順は **日付指定 → 日付空欄の毎回設定 → 標準シフト時刻** です。日付指定はその日だけ毎回設定を置き換えます。行の順序には依存しません。

標準日勤が09:00〜18:00・休憩60分の場合の例：

| 用途 | 個別の開始〜終了 | 休憩 | 実労働時間 |
|---|---|---|---|
| 早出 | 08:00〜18:00 | 60分 | 9時間 |
| 遅出 | 10:00〜18:00 | 60分 | 7時間 |
| 早退・時短 | 09:00〜15:00 | 30分 | 5時間30分 |
| 延長 | 09:00〜19:00 | 60分 | 9時間 |

- **時刻設定は割当を強制しません**。固定シフトも「割当可能な区分」の制限であり、出勤指定ではありません。月間実労働時間の完全一致など、他の必須条件が割当を必要にする場合はあります。
- 同じ職員・日付・シフトの重複は禁止です。毎回設定と日付指定の各1行は併用できます。日付ありなら作成期間内にし、現在存在する許可シフトを指定してください。
- 開始・終了は厳密な `HH:MM`（00:00〜23:59）。翌00:00終了は終了00:00と翌日終了TRUEで指定します。拘束時間は0分超〜24時間以内、休憩は0以上の整数分かつ拘束時間未満です。休憩空欄は0分で、標準シフトの休憩を引き継ぎません。
- 休息・希望休への持越し・月別の指定実労働時間と上限は、実際に適用された個別時刻・休憩で判定します。標準時間外の早出・延長もすべて労働時間に含めます。

### 役職の所属と配置要件

- サイドバーの「役職・配置要件」で複数の役職を追加・編集・削除できます。役職名は重複不可で、空欄・前後の空白・予約語「休」「希望休」「制限なし」は使えません。
- 配置条件は **必須なし**（所属の記録のみ）、**各シフト**（各シフトの標準時間内の各区間）、**1日のどこか**（勤務開始日単位）から選びます。必要人数は役職ごとに1〜職員数です。役職所属者数が足りないなど、条件が両立しない場合は作成不可になります。
- 職員表に役職ごとの「役職:名前」チェック欄が表示されます。複数役職への所属も可能です。役職名の変更時は、識別できる単一の変更であれば既存のチェック値を引き継ぎます。
- 結果のシフト表には職員ごとの役職名、日別配置には各役職のシフト配置数・時間帯別最少配置数・日単位配置数と必要人数が出力されます。役職要件は作成条件JSONにも記録されます。
- 旧「主任以上の配置」ラジオは既存操作との互換のため残しています。主任の配置条件を変更すると役職テーブルに反映されます。役職所属の正本は職員表の「役職:主任」チェック欄であり、「主任以上」フラグではありません。

### 時間帯別の必要人数・役職配置

- 必要人数を保証する範囲は、**勤務開始日とシフト区分ごとの標準開始〜標準終了の時間内だけ**です。個別時刻の境界で分割した各区間で最低N人を確保します。標準時間外の早出・延長部分には必要人数を設定しません。
- 例：標準日勤09〜18時、N=2で、終日勤務1人＋10〜15時の時短1人だけでは、両端が不足して作成不可です。終日勤務2人＋時短1人なら各区間2人以上を確保できます。日別の「人数」が3でも「時間帯別最少人数」は2です。
- 役職ごとに「各シフト」（`each_shift`）を設定すると、**標準時間内の各区間に設定人数以上**が必要です。途中だけ勤務する役職者では全区間を満たせない場合があります。複数人で時間帯を分担できます。
- 役職ごとに「1日のどこか」（`each_day`）を設定すると、開始日単位で設定人数以上が必要です。各シフト・各区間の役職配置は保証しません。
- **別シフト区分からの人数の借用はしません**。時刻が重なっていても他区分の職員で穴埋めできません。前日開始の持越し勤務を翌日開始分の配置として借用することもありません。
- **休憩の取得時刻・休憩タイムライン・代替配置は扱いません**。必要人数の検査は開始〜終了の拘束区間に基づくため、休憩中を含む常時人数の保証ではありません。標準シフト間の隙間や24時間全体のカバーも別途確認してください。

### 個別時刻の表示・結果CSV

- シフト表は標準設定と異なる勤務に時刻・休憩分を併記します。
- 日別配置の「勤務時刻」「休憩（分）」「勤務時間」は**標準シフト値**です。「担当者」に個人の適用時刻を表示し、「時間帯別最少人数」と各「時間帯別最少役職:名前」列で標準時間内の最低値を確認できます。役職別の日・シフト配置数と必要人数も列に表示します。
- 個別勤務明細CSVの列は「職員ID,氏名,日付,シフト,勤務時刻,休憩（分）,実労働時間」。個人ごとの実際の開始・終了・休憩控除後の時間を出力します。
- 職員別集計の「勤務時間」と月別労働時間の「実労働時間」も、標準時間×回数ではなく**各個人の適用時刻と休憩**から集計します。月またぎは勤務開始月に全時間を計上します。
- 曜日固定結果CSVの列は「職員ID,日付,曜日,固定シフト,割当シフト」。期間内の該当日ごとに表示し、解がある場合の固定シフトと割当シフトは一致します。この表の「固定シフト」は曜日固定の指定値であり、職員CSVの許可勤務帯の列とは用途が異なります。
- シフト回避結果CSVの列は「職員ID,日付,回避シフト,優先度」。実際に回避希望シフトへ配置された勤務だけを表示し、回避できた場合はヘッダーだけの空表になります。
- 回避ペア・個別時刻・曜日固定・シフト回避（選択内容や優先度）を変更した場合も、以前の結果・結果指標・結果CSVのダウンロードを非表示にします。再生成してください。入力表の保存ボタンは引き続き利用できます。

入力条件を変更した場合、古い結果は非表示になり、再計算が必要です。
同名の職員は登録できますが、職員IDは必ず一意にしてください。休み希望の重複行は1件として扱います。
空の希望行は無視しますが、片方だけの入力、不正な日付、未登録職員、対象期間外の日付はエラーにします。

### 職員CSV

```csv
職員ID,氏名,主任以上,固定シフト,月間実労働時間プリセット,月間実労働時間（時間）,月間上限（時間）
S01,職員A,True,深夜,160時間,,176
S02,職員B,False,制限なし,カスタム,120,140
```

「主任以上」は True / False または 1 / 0 を指定します。CSVはUTF-8で保存してください。
職員ID・氏名・主任以上だけのCSVも読み込めます（固定なし・時間指定なし・上限なし）。
職員一覧から保存したCSVには、設定中の各役職について「役職:役職名」列が追加されます。値はTrue/Falseまたは1/0です。役職列が1つでも含まれる場合、役職所属はその列だけで判定し、「主任以上」は役職所属に変換しません。旧CSVのように役職列がない場合は、主任以上がTrueの職員だけを役職名「主任」に所属させます（「主任」が設定中の場合）。その他の新しい役職は未所属になります。
旧時間設定列を含む職員CSVは、値が空欄や0でも読み込みエラーになります。自動変換はしません。
旧形式を読み込めない場合は、新しい職員一覧で固定シフト・月間実労働時間・上限を確認して入力し直し、「職員CSVを保存」で新形式として保存し直してください。
このCSV例は列と値の形式例です。実際の対象日数と勤務時間単位で完全一致できる指定時間を設定してください。
職員一覧だけで実行可能とは限りません。例えば三交代・N=2で各シフトに主任以上が必要な場合、全員が各標準時間をカバーできても毎日最低6人、そのうち主任以上が最低3人必要です。個別の短時間勤務などがあれば、さらに多くの配置が必要になったり作成不可になったりします。

### 休み希望CSV

```csv
職員ID,日付
S01,2026-11-03
S02,2026-11-04
```

上記は形式例です。実際の対象期間内の日付に置き換えてください。

### 回避ペアCSV

```csv
職員ID A,職員ID B,優先度
S01,S02,
S01,S03,高め
```

3列すべてのヘッダーが必要です。優先度空欄は普通です。以前の「重み」列（1〜100）のCSVも読み込め、1〜4＝低め、5〜19＝普通、20〜49＝高め、50〜100＝最優先に変換します。同じ組を逆順で追加しないでください。全項目空欄の行は無視します。

### 個別勤務時刻CSV

```csv
職員ID,日付,シフト,開始,終了,翌日終了,休憩（分）
S01,,日勤,08:00,18:00,False,60
S01,2026-11-03,日勤,10:00,18:00,False,60
S02,,日勤,09:00,15:00,False,30
S03,,夜勤,20:00,00:00,True,0
```

7列すべてのヘッダーが必要です。日付空欄は毎回適用し、S01の11月3日は日付指定の10:00開始を優先します。日付が必要な設定を空欄にすると毎回設定として扱うため注意してください。
翌日終了はTRUE/FALSEまたは1/0（空欄はFalse）、休憩空欄は0分です。未登録ID・不正な時刻や日付・未知のシフト・重複設定は拒否します。
この例は形式例であり、「日勤」「夜勤」が現在のシフト一覧にあり、職員が登録済みで、指定日が作成期間内の場合に使用できます。必要人数などを満たすことや、これらの職員が必ず配置されることを意味しません。
両CSVともUTF-8で保存し、「配慮・個別勤務」の各CSV読込から反映します。保存した作成条件JSONにも回避ペア・個別勤務時刻が記録されますが、JSONの再読込機能はありません。

### 曜日固定CSV

```csv
職員ID,曜日,シフト
S01,月,日勤
S01,木,日勤
S02,金,準夜
```

3列すべてのヘッダーが必要です。曜日は「月,火,水,木,金,土,日」のいずれか1文字で、日付・数字・「月曜」などは指定できません。同一職員・曜日の重複は禁止です。全項目空欄の行は無視します。これは登録済みIDと現在のシフト名を使う形式例であり、希望休などと両立することを保証しません。

### シフト回避CSV

```csv
職員ID,回避シフト,優先度
S01,"[""深夜"", ""準夜""]",高め
S02,"[""準夜""]",低め
```

3列すべてのヘッダーが必要です。「回避シフト」はJSON文字列配列で、CSVではフィールドを二重引用符で囲み、内部の二重引用符を2個にエスケープします。例えば1行目をCSVとして読むと回避シフトの値は `["深夜", "準夜"]` になります。区切り文字で並べた文字列やJSONオブジェクト、数値を含む配列は使用できません。同じ配列内のシフトの重複、同じ職員IDの複数行、未登録ID・未知のシフトも拒否します。

優先度は低め・普通・高め・最優先（空欄なら普通）です。旧形式の「重み」列も上記と同じ区分で変換します。空配列 `[]` または回避シフト空欄は希望なしとして扱います。両CSVともUTF-8で保存し、「04 曜日固定・シフト回避」の各ファイル選択と「CSVを曜日固定に反映」「CSVをシフト回避に反映」で読み込みます。一方の取込時も他方の入力、職員、希望休、回避ペア、個別勤務時刻を保持します。不正なCSVは反映せずエラーを表示します。作成条件JSONにも曜日固定・シフト回避を記録しますが、JSONの再読込はできません。

## 守る条件と最適化

### 必須条件

- 各職員は1日1勤務まで。
- 毎日、すべてのシフトの標準時間内の各区間に最低N人を配置（個別勤務時刻を反映、休憩時刻は対象外）。
- 設定した各役職の「各シフト」要件は各区間、「1日のどこか」要件は開始日ごとに必要人数を配置。
- 休み希望日は勤務を割り当てない。希望を緩和して解を作ることはありません。
- 連続勤務の上限を守る（初期値5日、設定可能）。
- 勤務間の最低休息時間を守る（初期値11時間、設定可能）。
- 「前日より早い出勤を禁止する」が有効なら、隣接する勤務開始日の実際の開始時刻を同じか遅くする（任意・初期値は無効）。開始割当なしの日で比較だけをリセットし、最低休息は別に守る。
- 職員の固定・許可シフトと月間上限を守る。
- 期間内の各該当開始曜日に曜日固定勤務を割り当てる。他の必須条件と矛盾しても固定を緩和しない。
- 月間実労働時間が指定されていれば、暦月ごとに日割り・四捨五入した整数分と休憩控除後の合計を必ず完全一致させる。0は勤務禁止、未設定なら時間指定なし。

### 勤務時間の定義（初期値）

| シフト | 時間 | 日付の扱い |
|---|---|---|
| 深夜 | 00:00–08:00 | 表記日の当日 |
| 日勤 | 08:00–16:00 | 表記日の当日 |
| 準夜 | 16:00–24:00 | 表記日の当日 |

勤務間休息は終了から次の開始までの実時間で計算します。
初期値では準夜→翌日の深夜は休息0時間、準夜→翌日の日勤と日勤→翌日の深夜は休息8時間です。
「深夜勤務後は翌日丸ごと休み」というルールではありません。

- 開始は表記日の00:00〜23:59、終了は当日または翌日です。1勤務の長さは0分より長く24時間以内にしてください。
- 24:00終了は「終了00:00＋翌日終了」で設定します。同じ開始・終了時刻で翌日終了なら24時間勤務です。
- 人数・主任以上の配置は**勤務開始日とシフト区分**を基準に、上記の標準時間内の区間ごとに判定します（主任の1日指定を除く）。1日1勤務・連続勤務も勤務開始日基準です。
- **希望休は暦日全体**を対象にします。前日から希望休当日に持ち越す勤務も禁止します。ただし希望休当日の00:00ちょうどに終わる勤務は許可します。
- 勤務の重複は禁止し、設定した最低休息を確保します。翌日終了の長い勤務については、中1日空いた場合の休息も検査します。
- 日別配置CSVの時刻・休憩分・勤務時間は標準値です。個別勤務明細CSVには個人別の実際の値、職員別集計CSVには実労働時間合計、条件JSONには標準時刻と個別設定が含まれます。
- 勤務時間は開始〜終了の経過時間から休憩分を控除します。勤務間の休息は拘束時間の終了から次の開始までで、勤務中の休憩は含めません。
- 休憩取得時刻と代替要員は計画しません。休憩中も含めた常時人数の確保は別途確認してください。
- 標準シフト間の時間の隙間・重複は自動調整しません。「各シフトN人」は同一区分・同一開始日の標準時間内での区間別人数であり、24時間全体の切れ目ないカバーや休憩中の人数を自動保証するものではありません。

### 目的関数

必須条件をすべて満たす範囲で、次の辞書式の優先順位を守る重みで最適化します。

1. **総配置数**を最小化。
2. **回避ペア衝突＋回避希望シフトへの配置の重み付き合計**を最小化（ペアは同じ開始日・同一区分の組ごと、シフト回避は実際の該当勤務ごとに加算）。
3. **全職員間の勤務日数の最大差＋各勤務帯の勤務回数の最大差**を最小化。

ペア・シフト回避のために配置数を増やしたり、回数の公平さのために両者の合計コストを増やしたりはしません。ペア回避とシフト回避は同じ優先段階で合算し、相互に別の優先順位は付けません。
標準時間内の各区間の最低N人は必須ですが、N人超の配置も許容します。
指定実労働時間との完全一致や短時間勤務者を含む時間帯カバーのため、区分全体の割当人数がN人を超えることがあります。指定時間との差を最小化する目的はありません。
固定勤務や個人の指定時間・休み希望によって、全員の回数が同じになるとは限りません。指定時間と月間上限は常に必須制約です。

### 結果の区別

- **最適解**：必須条件を満たし、この目的関数について最適性を証明済み。
- **実行可能解**：必須条件を満たすが、計算時間上限で最適性は未証明。
- **作成不可**：入力不足の事前検査、またはソルバーにより条件の両立不可を確認。
- **時間内に解が見つからない**：実行可能か不可能か未確定。「作成不可」とは区別します。

作成後はソルバーとは別の処理で、人数・役職（標準時間内の区間別も含む）・希望休・重複勤務・休息・連勤・許可シフト・曜日固定・有効時の前日より早い出勤禁止・月別上限・指定実労働時間との完全一致を、適用された個別時刻で再検査します。回避ペア・シフト回避はソフト制約なので、衝突や回避希望への配置を必須条件違反とはしません。
解がない場合、明らかな日別不足は表示できますが、複雑な矛盾の最小原因集合までは特定しません。

## 制限と注意

- 対象期間の前日・翌日以降の勤務は入力できません。境界をまたぐ連勤・休息・出勤開始時刻の順序は別途確認してください。
- 最終日開始の勤務は翌日に終了することがあります。期間末の希望休を保護する場合は、その日まで対象期間を含めてください。
- 労働基準法上の休日、週単位の労働時間、変形労働、個別の法的要件、有資格者、任意の単一日付だけの出勤・シフト割当の強制、勤務帯ごとの必要人数の変更は未実装です。毎週の曜日固定による出勤指定には対応します。日付指定の個別時刻は設定できますが、その時刻設定だけでは出勤を強制しません。
- このツール単体で法令や就業規則への適合を保証しません。運用前に責任者が確認してください。
- 1人1日1勤務というモデルであり、深夜と準夜を同日に組み合わせる運用には対応していません。
- データベースへの永続保存や自動保存はありません。画面の再読み込みやサーバー停止に備え、入力CSVを保存してください。
- 職員データを外部APIへ送信しません。初期設定では127.0.0.1のみで待受します。CSVの保管・共有は個人情報として適切に管理してください。
- 作成条件JSONは記録用です。現時点で再読込機能はありません。
- 並列探索のため、同一入力でも同点の別シフトが得られる場合があります。
